# Research Seed — Cradle Jarvis-as-Kind Macro Strategy

**Audience:** subsequent critique-chain agents  
**Scope:** macro strategy only. No implementation. No Jarvis internal function taxonomy.  
**Date:** 2026-08-02

## User intent (authoritative)

1. Design how Cradle should host a Jarvis-like super-intelligence that manages the whole app platform and beyond — including session-level orchestration across heterogeneous model workers.
2. Learn from adjacent agent-product categories (Operator-workplace, thin multiplexer, builder-orchestrator, meta-harness, teammate work-graph, single-agent multi-surface runtime) — research clones kept local, not named in public artifacts.
3. Jarvis is **not one agent**. Jarvis is a **kind of agent** (species / AgentKind), analogous to MCU J.A.R.V.I.S. as Stark's system organism — many capabilities, one continuous system identity.
4. Do **not** discuss implementation.
5. Do **not** depict Jarvis internals (no Function maps, no MCP tool lists, no phased engineering plans for Jarvis guts).
6. Decide the **super-macro scheme** and inventory **what is still missing** in Cradle today.
7. Keep pushing via multi-round adversarial agents until a final constitutional artifact exists.

## Hard constraints from Cradle

- **IRON LAW:** Cradle must not own Claude Agent SDK (or peer-native) turn/session scheduling. Cradle projects native events into UI Runs, messages, SSE, queue, observability. Forbidden: close user run on empty/early `result` then open system synthetic run to continue the same Claude work.
- **Ownership:** read across, write within; every feature has a clear owner.
- **Cognition stack (Plan 061):** L5 Orchestration → L4 Harness → L3 Recall → L2 Chronicle → L1 Evidence; Execution cross-cut = Chat Runtime + providers.
- **Product thesis today:** "every agent, one home" — desktop-first local control plane for heterogeneous AI agents; privacy-first.

## What Cradle already has (compressed)

- Heterogeneous runtime projection: claude-agent, codex, kimi, opencode, acp-chat, jar-core (HiJarvis), plugin runtimes.
- Session / Run / Queue / Steer / Session Await / Work / Issue Agent / Automation / Thread Handoff.
- Catalog surfaces: `chat` | `jarvis` (placement, not species).
- Agent Identity personas; mutation actors `user|agent|system|provider-target`.
- HiJarvis = ambient personal surface + `jar-core` runtime + preferences — **not** a platform species.
- Provider-native crews as provider-threads (not Cradle multi-session orchestration).
- Sparse cradle MCP tools (recall + manage_pull_request); L5 mostly human/CLI driven.
- No first-class AgentKind; no unified control-plane situation picture; no honest delegate/receipt contract as platform semantics; no Kind-scoped continuity memory; weak platform-kind trust/blast-radius; ambient observes but has no propose/act policy layer.

## Competitive landscape (compressed)

| Family | Bet |
|--------|-----|
| Operator-workplace products | Agents as teammates; Operator workspace; platform skill |
| teammate work-graph products | Work graph (issues); polymorphic actors; squads; builtin platform skills |

Cradle's open strategic slot: local control tower × heterogeneous projection × work control plane × **platform-owned species** (mostly missing).

## Prior draft macro claims (to be attacked, not assumed true)

1. Jarvis = AgentKind parallel to Coding Kind; not a chat agent upgrade.
2. Build order: control-tower honesty + work-plane completeness **before** expanding species power.
3. Platform center of gravity may need to shift from Session/Chat toward Work/Issue as work graph, with Session as execution carrier.
4. Orchestration ambition: platform supplies honest delegation semantics; strategy stays with Kind/human — unless product later chooses a "legion mode."
5. Initiative red line: default propose-only vs policy-gated autonomy is unresolved.
6. Eight gaps: species layer; operable control plane for species; unified situation model; delegate–receipt contract; Kind-level memory; trust/blast radius; sense→act policy; constitutional vocabulary.

## Acceptance criteria for the final artifact

The final document must:

1. State Cradle's multi-year platform constitution in plain language.
2. Resolve (or explicitly leave open with rationale) the five super choices: species-first-class; build order; product center; orchestration ceiling; initiative red line.
3. List strategic gaps ranked by "blocks platform species from existing."
4. Contain **zero** implementation plans, APIs, schemas, Function taxonomies, or sprint phasing.
5. Be self-contained for a human decision-maker who has not read this seed.
6. Be honest about tradeoffs and uncertainties.
