# Issue Module

Workspace-scoped issue capability. Owns workflow statuses, milestones, issue CRUD, due dates, comments, raw field-change audit history, server-projected Activity, relations, context refs, session links, linked session read projection, delegation markers, actor provenance, and issue search semantics. Kanban reads this data as board/list/table views but does not own issue semantics.

Issue also owns Issue–execution association semantics: the shared-workspace invariant (a non-null `linkedIssueId` requires the participant and Issue to share one non-null workspace), the link/unlink/relink workflow, and the typed previous/next transition returned by association mutations. Session and Session Group own reads and writes of their own `linkedIssueId` columns through narrow seams (`session/issue-association.ts` and the Session Group linked-issue validator port); this module never writes participant tables. Direct `/sessions/:id/linked-issue` routes and participant create/update-with-link paths all run the same invariant, so rejected associations are atomic and preserve prior state.
Comment and Activity responses include server-resolved actor projections; clients should not infer AI identity from raw agent, provider target, or profile IDs. `provider-target` is a first-class Issue actor kind rather than being folded into system.

## Files

- `index.ts`: Elysia `/issues` routes, OpenAPI metadata, generated CLI descriptors, Activity projection reads, raw field-change audit reads, linked session reads, and the Agent-facing issue move route that accepts status name slugs. Also hosts `issueExecutionAssociation`, the Issue-owned `/sessions/:id/linked-issue` get/link/unlink routes that keep their stable Session URL prefix while returning typed association transitions.
- `model.ts`: TypeBox schemas for issue requests and responses, including due dates, Activity items, raw field-change rows, comment author projections, source chat session provenance, linked sessions, and `statusName` request aliases for Agent workflows.
- `service.ts`: Issue workflow, key generation, workspace transfer semantics, default status assignment to Backlog, status name/slug resolution, workspace-scoped status/milestone/parent validation, actor provenance, source chat session persistence, raw field-change recording, server-owned Activity projection, unified assignee/delegation markers, comment author projection, search matching, relations, context refs, linked session reads, and session link semantics.
- `execution-association.ts`: Issue-owned association workflow — `assertExecutionIssueWorkspaceMatch` invariant (`issue_workspace_mismatch`, HTTP 409), Session link/unlink transitions, and the `assertSessionLinkedIssue`/`assertSessionGroupLinkedIssue` gates the composition root registers into participant modules for create/update-with-link.
